# P2 解码裁决 · 同一基座权重,只换解码方式(2026-09-03/04,RTX 5090 D,vLLM 0.28)

一句话结论:**W2 报告里「三种配方全线无增益」的成绩表,测的是解码协议不是模型。同一份 Qwen3.5-4B 权重,
不训练、只把贪心解码换成官方推荐采样(或在撞上限时替它写上「</think> 答案:」),CMExam 严格口径从 59.6% 到 74.0%,
三卷收尾率从 33~74% 到 100%,复读归零。** 训练臂的所有已发表数字都还没在这个正确的测量制度下重测过。

完整对照表(含 v2 存档臂、配对 CI、Holm/BH 校正、MDE):[usability-v3.md](usability-v3.md);
逐题标签在 `reports/runs/base-v3-*/*.usability.jsonl`,`uv run python -m medforge.eval.usability --from-tags --baseline base-v3-greedy` 可复算。

## 1. 设计

五条臂,全部用**原装基座权重**,同一批固定种子抽样卷(CMExam 2000 / CMB-val 280 / MedXpertQA 1000,与 v2 存档逐题可配对),
同一个判分器(v3:截断守卫 + 规则层只看 `</think>` 之后 + LLM 兜底),同一台机器同一个 vLLM 实例,按顺序跑完:

| 臂 | 解码 | 预算 | 其它 | 想回答的问题 |
|---|---|---|---|---|
| greedy | temperature 0 | 8192 | — | v2 协议在新引擎上复跑:存档还能不能信 |
| sample | 官方卡思考模式:1.0 / top_p 0.95 / top_k 20 / min_p 0 / presence 1.5,seed 42 | 32768 | — | 按官方说的解码,模型本来的水平 |
| forcing | temperature 0 | 8192 | 撞上限时接回思考流,强写 `</think>\n\n答案:` 再续写 32 token(s1 式) | 「交不了卷」能不能靠一条 harness 补丁修掉 |
| abstain | temperature 0 | 8192 | 提示词允许写「答案:不确定」 | 弃权能力是不是 prompt 就能拿到 |
| greedy32k | temperature 0 | 32768 | — | 把「预算不够」和「贪心退化」拆开 |

预注册的决策规则(跑之前写下):**若 sample 臂三卷未收尾率降到个位数且 CMExam 严格口径 ≥ 72%,则降分主要是解码工件,
主表换 v3 采样协议,训练线的目标从「涨准确率」改为「同分而便宜」。**

## 2. 结果(严格口径 = 写完 ∧ 结论可抽出 ∧ 答对;括号内为收尾率)

| 臂 | CMExam n=2000 | CMB-val n=280 | MedXpertQA n=1000 | 复读率(三卷) | completion tokens 均值(三卷) |
|---|---|---|---|---|---|
| base-v2 存档(贪心 8k,8 月) | 59.2 (74%) | 48.9 (74%) | 10.9 (35%) | 19 / 15 / 35% | — |
| greedy(贪心 8k,复跑) | 59.6 (74%) | 46.4 (71%) | 10.2 (33%) | 18 / 13 / 35% | 5.0k / 5.5k / 7.5k |
| **sample(官方采样 32k)** | **74.0 (100%)** | **60.0 (100%)** | **25.1 (100%)** | 0 / 0 / 0% | 5.2k / 5.7k / 8.4k |
| **forcing(贪心 + 强制收尾)** | **73.5 (100%)** | **57.9 (100%)** | **27.4 (100%)** | 16 / 15 / 37%¹ | 5.0k / 5.5k / 7.6k |
| abstain(贪心 + 允许弃权) | 57.6 (69%) | 45.7 (70%) | 9.9 (29%) | 24 / 20 / 46% | 5.3k / 5.8k / 7.6k |
| greedy32k(贪心 32k) | 63.8 (82%) | 49.3 (80%) | 13.9 (46%) | 18 / 20 / 55% | 9.5k / 10.6k / 21.4k |

¹ forcing 的复读率是被强制收尾**之前**的思考流仍在复读(指标看尾部 4000 字符,含被接回的循环段),它衡量的是「贪心有多容易转圈」,不是交付质量。

配对检验(vs greedy,同一批题):sample 三卷 +14.4 / +13.6 / +14.9pp,forcing +13.9 / +11.4 / +17.2pp,
95% CI 下界均 ≥ +6.8pp,Holm 与 BH 校正下全部成立;abstain 三卷与 greedy 无差异(p 0.08 / 0.89 / 0.82)。

对训练线最要紧的一行:v2 存档里「唯一正结果」sft-r1-v2 的 CMExam 严格口径 62.2%,与 greedy 复跑相比 +2.6pp(p=0.028,Holm/BH 均不过),
与正确解码的基座相比 **−11.8pp**。

## 3. 四个判断

1. **决策规则 R1 触发。** sample 臂三卷收尾 100%、退化 0%、CMExam 74.0% > 72%。W2 的「全线降分」是坏尺子量出来的。
2. **分数几乎全由「把答案逼出来」贡献,而不是「想得更好」。** forcing 只加了一条 32 token 的续写补丁,三卷与 sample 持平甚至略高
   (MedXpertQA 27.4 vs 25.1)。被强制的 513 道 CMExam 题答对 56%,正常写完的 1487 题答对 81%:模型在转圈之前其实已经想到了答案。
3. **弃权不是 prompt 就能拿到的能力。** 提示词明确允许写「不确定」,2000 题里只有 1 题这么写,分数与贪心无差异。要弃权,得训练或用置信度阈值,这条线不必再试 prompt。
4. **预算不是问题,贪心退化才是。** greedy32k 把预算翻四倍,CMExam 只从 59.6 到 63.8,三卷仍有 18 / 20 / 55% 的题一直写到 32768 才被掐
   (真死循环,给多少预算都不够),每题均 token 却涨到贪心 8k 的 1.9 倍。换采样或强制收尾是唯一出路。
5. **零假设翻转率 20%。** 同一权重、同样贪心,8 月与 9 月两次跑之间有 404/2000 题严格口径对错翻转。W2 §3 把 DPO 的「413 题翻转」当作
   训练改变了模型的证据,现在看那和什么都不做的翻转量一样大,那条证据作废;翻转主要来自贪心下的截断彩票。

## 4. 对项目的含义

- **主表换 v3 协议**:官方采样参数 + 32768 预算 + 截断守卫 + finish_reason 落盘。默认解码参数在评测 CLI 里切到 v3(见 `eval/run.py`)。
- **训练臂全部需要在 v3 下重评才能与基座横比。** DPO 权重在 HF(`fang04/medforge-qwen3.5-4b-dpo`),可直接重评;两个 SFT 臂的合并权重未上传,
  要么找回租卡机上的 checkpoint,要么按 W2 审查里修好的配置重训。在此之前,README 的 W2 成绩表只能作为「v2 协议下的历史数字」保留。
- **新的比较基线是 base + forcing(或 sample)**,不是贪心基座。任何微调要证明自己,得先赢过这个免费补丁:CMExam 73.5 / CMB-val 57.9 / MedXpertQA 27.4。
- **训练线的目标改为「同分而便宜」**(或者干脆不训):正确解码的基座每题 5~8k token,这是要打的成本基线。「让模型答得更对」这条轴,4B 上目前看不到空间。
- **部署侧直接可用的结论**:线上服务用 forcing 或 sample 协议,不要贪心;forcing 对延迟几乎零影响(只对撞上限的请求多 32 token)。

## 5. 局限

单次采样(seed 42),未做多 seed;CMB-val n=280 的最小可检出差异约 7~9pp,该卷只能看方向;LLM 兜底判卷仍是 deepseek-chat 且未按选择题重校准
(v3 臂声明率 90~98%,兜底占比比 v2 小得多);MedXpertQA 25~27% 对 10 选项卷仅为随机基线的 2.5 倍,是「真写完了的 25%」,不再是从草稿刮出来的;
本次全部在 RTX 5090 D + vLLM 0.28 上跑,greedy 复跑与 8 月存档配对 p=0.73,引擎漂移可忽略。
