## 分歧分析(7 条,明细见 calibration-run.log)

全部为开放题语义边缘案例:数值取整口径(85.4 vs 85)、诊断表述框架不同

## 2026-09-04 补校准 · LLM 兜底层按它实际判的题重测

W2 审查指出:上面 200 题里的 80 道选择题全被规则层接住,LLM 层只判过 119 道开放题(单独一致率 112/119 = 94.1%),
而三卷评测里 LLM 层实际判的 100% 是选择题(规则层抽不出字母的那批)——校准分布与工作分布不重叠。

**做法**:从七个存档 run(base-v2 / sft-v2 / sft-r1-v2 / dpo-v2 / base-v3-sample / base-v3-forcing / base-v3-greedy)里抽
`method == "llm"` 且作答已收尾的题,按卷分层等额抽 150(CMExam 50 / CMB-val 50 / MedXpertQA 50),
用**另一个模型**(deepseek-v4-pro,思考模式,提示词与判卷员不同、要求先抽出考生最终选项再比对)做代理标注,
4 条代理也无法判定,146 条进分母。`uv run python -m medforge.verify.calibrate data/calibration/pending-mcq.jsonl --llm --label-field proxy_correct` 可复算。

**结果**(用现行验证器重判这 146 题):

| 判分路径 | 判定数 | 一致率 | Cohen's κ | false-accept | false-reject |
|---|---|---|---|---|---|
| 规则层(W2 审查后的新抽取器已能接住的) | 74 | 100.0% | 1.00 | 0 | 0 |
| **LLM 层** | 72 | **98.6%** | 0.97 | 1 | 0 |

唯一分歧 medxpertqa-834:考生结论描述了机制、未明确选项字母,judge 按机制推断判对,代理按「未明确选项」判错——属边界情形,方向是 false-accept。
当时落盘的 LLM 判定与代理标注的一致率 146/146 = 100.0%(含被新抽取器接住的题)。

**局限**:代理标注不是人工标注(与上面 200 题「强模型代理 + 人工抽检」同一口径),待人工抽检 30 条后落 `human_correct`;
judge 仍是 deepseek-chat,与被评模型之一(base 采样臂)无同源问题,但与代理标注模型同厂——两者提示词与推理模式不同,仍不是独立来源。

## 2026-09-05 补记:判卷员换成本机 Claude Code(订阅额度,不用 API key)

同一套 146 题 MCQ 校准集(标签列 proxy_correct),规则层先判、规则层弃权的 72 条落到 LLM 层,
用 `MEDFORGE_JUDGE_PROVIDER=claude-code` 分别跑两个模型:

| judge | LLM 层判定数 | 一致率 | Cohen's κ | false-accept | false-reject | LLM 层主动弃权 | 每次调用 |
|---|---|---|---|---|---|---|---|
| deepseek-chat(09-04 报告) | 72 | 98.6% | 0.97 | 1 | 0 | 0 | ~1 s |
| **claude-sonnet-5** | 70 | **100.0%** | 1.00 | 0 | 0 | 2 | ~6.3 s |
| claude-opus-5 | 71 | **100.0%** | 1.00 | 0 | 0 | 1 | ~7.2 s |

- 两个 Claude 模型都零误判;多出的弃权全是诚实的 `correct: null`(考生答卷被截断、没有最终选项),不是调用失败。
- claude-haiku-4-5 未测:当天订阅额度用尽(5 小时窗口),不补——判卷员已有零误判的选项,没必要再花额度试更弱的。
- **决定**:判卷兜底用 `claude-sonnet-5`(更快),代理标注用 `claude-opus-5`(与判卷员不同模型,保持独立性)。
  每次调用 ~31k 缓存上下文,连续调用命中缓存;一卷 2000 题的兜底不到 30 次,额度可忽略。
- 政策线:Claude 只做判题与答题(判卷、代理标注、参照跑分),**不做蒸馏老师、不给 DPO 偏好对打标**——
  Anthropic 消费者条款第 3 条禁止用输出训练模型;老师继续用条款允许蒸馏的 DeepSeek 或本地开源模型。
